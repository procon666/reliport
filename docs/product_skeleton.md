# 产品骨架：以「我的口径」为准的投资决策辅助（2026 · 方向文档）

> 状态：产品方向文档（用户拍板：可信是入场券、订制是卖点；先押投资决策辅助场景）。
> 引擎已验证能力直接复用；本文档中标注 **【新设计】** 的部分尚未验证，属产品化待办。
> 目的：给"私人订制报告"一个可评审、可拆里程碑的骨架，不再空想。

## 0. 一句话定位

**一个以用户自己的口径体系为准、自动勘误、越用越懂他的投资决策辅助引擎。**
可信解决"敢不敢用"，订制解决"凭什么选你而不是 Perplexity"——纯可信做不出
溢价，因为"通用正确"已免费可得；壁垒在"以我的口径为准"的订制与置信度。

> **卖点补强（2026 评审）：展示多元渠道 = 信任，本身就是卖点。**
> 用户信任数据产品，信的不是"它替我判断"，而是"**我看到了所有说法，它没藏**"。
> 因此产品默认姿态不是"给一个数让你拍板"，而是**把多元来源/口径差异摊开给人看**
> （谁说的、原话、差在哪），让透明本身产生信任；拍板只是用户看明白后的
> **可选深化动作**（零负担），不是被强加的任务。信任公式：
> `信任 = 透明展示（多元渠道）× 订制（我的口径）`——两者同源，互为放大。

## 1. 核心机制（与已验能力的映射）

```
多来源资料
   │  ① 自动分歧检出（已验：AI对齐+规则键闸门 → 同题多口径清单）
   ▼
自动消解勘误（机器承担绝大部分，用户无感）
   ├─ 口径分层归因（已验：口径差 vs 真冲突，谁对谁错不硬判）
   ├─ 对账纠错     （已验：质检员逐字对账，改数即抓）
   ├─ 单位/时间/键 归一（已验：规则键闸门）
   ▼
生成报告（已验：约束式写作——AI 答题，规则出题）
   │  ② 同题多口径处 → **默认并陈展示**（谁/口径/数值/差在哪），证据视图点开可看
   ▼
用户可表态（可选：并陈处点"以后按这个看"→ 沉淀；不表态也完整受用）
   ▼
下一份报告自动套用 → 订制越用越贴；从未表态的用户只持续享受透明
```

三层负载边界（同一条轴：AI 管语义、规则管确定、用户管领域）：
- **机器错**（张冠李戴/单位换算/口径混用）→ 系统自动纠，用户无感；
- **语义级判断**（该用哪个口径、哪家源更权威）→ 系统筛出 → 用户拍板 → 沉淀；
- 置信度 = 机器核源数 × 用户口径/信源加权（**只有这个系统算得出**）。

## 2. 订制维度定义（数据结构）

三维：**口径(gauge) / 信源(source) / 关注指标集(metrics)**。
优先级：口径+信源先做（直接连着冲突消解，能立刻做出差异化）；指标集后放
（功能补全，不构成壁垒）。

### 2.1 偏好记录结构（sqlite 表 `preference`）

```python
Preference = {
  "domain": "白酒行业",              # 作用域：领域/主题/公司，层级树
  "dim": "gauge" | "source" | "metric",
  "key": "贵州茅台·营业收入",        # 作用对象（指标/公司/话题键）
  "value": "财报口径",               # 偏好值（口径/源/指标）
  "origin": "expert_default" | "user_pick" | "user_correct",
                                    # 来源：默认专家 / 被问选择 / 主动纠错
  "hits": 3,                        # 累积确认次数（置信度加权分母之一）
  "updated_at": "2026-07-20",
}
```

作用域树（层层递进，子级覆盖父级）：
`领域(如 白酒) → 主题(如 贵州茅台) → 指标(如 营业收入)`
提问命中规则：查最具体的偏好；无则向上层回溯到领域级默认，再退回专家默认。

### 2.2 偏好如何参与生成（三处挂点）

| 偏好 | 参与点 | 效果 |
|---|---|---|
| gauge | 分歧清单 → 口径选中 | 带偏好的口径作报告主叙事；其余口径仍须交代（约束式不变） |
| source | 置信加权 | 用户高看源 × 更高权重；低看源需更硬证据才入主叙事 |
| metric | 报告大纲 | 只展开用户关注的指标；未关注指标折叠或省略 |

置信度展示的用户语言：
`该数在你偏好的口径下，被 N 家独立来源确认，你本人已确认 M 次`
（替代机器自评分数；N 来自规则核源，M 来自拍板史。）

> **双通道物理隔离（2026 工程评审红线，优先级最高）**：
> 用户决断史（偏好/拍板 M）**只能进"呈现通道"，永远不许进"证据通道"**——
> 否则偏好加权直接改写机器分，会造成**回音壁**：用户上期采信财报口径 862 亿，
> 本期新审计证据已推翻它，但偏好把 862 加权抬高高亮，用户越看越觉得自己选对了，
> 新证据反被压暗——系统本应勘误，却变成"帮用户确认偏见"。

| 通道 | 输入 | 职责 | 能否被用户影响 | 谁说了算 |
|---|---|---|---|---|
| **证据通道**（引擎层，已有） | n_support / top_cred / 冲突强度 | 判定"哪个口径更可信"、自动勘误 | **不能** | 勘误永远压过偏好 |
| **呈现通道**（产品层，待建） | 证据分 + 偏好命中 + M | 决定默认展开哪个口径 / 措辞 / 高亮谁 | 能（用户偏好做主） | 偏好只管"按你的口径展示" |

- 偏好管"按你的口径**展示**"，勘误管"这个数本身**错了**"——不在同一层竞争；
- **机器错→自动纠，用户无感**保持最高优先级：即使用户采信的口径被新证据推翻，
  勘误也静默纠正，措辞尊重用户："你之前按 X 口径看，新证据显示 Y 更可靠，
  已帮你切换，可回退"——接上 §5 的一键回退。

> **回显承担双重职责（2026 评审补）**：
> ① **订制感**——报告必须显式告诉用户"因为你的偏好，这里我用了财报口径"，
>    让"这是我的报告"可感知（数据变化本身不产生订制感，可见的回显才产生）；
> ② **合规留痕**——用户拍过板的每个地方都要有可追溯标记
>    （"此处按你的采信：财报口径，2026-07-20 你选择"），一旦出事可证明
>    "选 A 是你自己点的"。回显不是装饰，是产品责任与合规的地基。

## 3. 拍板交互流

### 3.1 主交互：默认并陈展示 → 可选确认/纠偏 → 沉淀（透明为主，拍板可选）

> 评审修正（2026）：主姿态不是"被问→必须选"，而是"**默认把多元渠道摊开给你看，
> 你想固定口径再表态**"。展示多元渠道本身就是信任与卖点；拍板是可选深化动作。

- **默认姿态（零操作）**：凡遇同题多口径，报告**默认并陈展示**——每条注明
  谁说的（来源）/什么口径/数值/差在哪（证据视图）。用户不点任何东西也能读全，
  透明本身就是价值；从不表态的用户也完整受用（只是不进入订制）。
- **深化动作（可选、低摩擦）**：用户若想固定口径，在并陈处点"以后按这个看"
  → 沉淀偏好（origin=user_pick），当前段落立即切换并回显（订制感+合规留痕）。
- **确认 vs 纠偏**：看到并陈后点"同意这条"是轻确认；在别处发现系统默认错了、
  主动"纠正"是重信号（user_correct 权重更高，原则不变）。
- **分层呈现（防信息过载）**：首屏只给一句话"这里有 N 套说法，差在 X"；
  完整渠道证据（原话/时间/链接）点开才展开。信任 = 想看时一定能看到底，而不是被迫看全部。
- **收敛**：已表态的 (domain,key) 不再重复打扰；**未表态的用户不弹窗**
  （避免审问感）——他只会持续看到并陈，直到某天想定口径。

### 3.2 辅交互：「我的口径」维护面板

- **不是启动入口**，是熟用户进阶操作（用了数份之后微调才去）；
- 能力：增删信源、改默认口径、看每条偏好"在哪些报告里生效过"（可追溯可回退）。

### 3.3 原则

默认让用户**被服务**：主姿态是"并陈已摊开、看得见底"（零操作即受用），
表态/纠偏是可选深化，不要求**被维护**；
只有用户主动纠错（user_correct）比被动确认（user_pick）权重更高——他主动纠的
比被动选的更真实。

## 4. 第一份报告上手流程（防早期劝退）

1. **输入**：用户给一个主题（如"我看好白酒，帮我盯贵州茅台/五粮液"），或选默认关注池；
2. **生成**：用**默认专家口径**（信源按权威度、口径按官方/行业协会标准，如
   中汽协/财报口径）先生成一份完整报告——**先证明"我能给你一份对的报告"**；
   且报告**默认自带证据视图**：每个关键数字旁有轻量的"谁说的/几套口径"提示，
   点开可见原话与来源——先让用户**看得到底**，信任在第一次阅读时建立；
3. **边读边纠（可选）**：报告内"这里口径不对 / 我不看这个指标 / 换这个源"，
   点一下即沉淀偏好，当前段落立即按偏好重排并回显；
4. **第二份起**：自动套用偏好 → 订制越用越贴；未表态的用户不被打扰，只持续
   享受透明并陈（随时可表态）。

上手体验 = 被服务起步，慢慢变成专属；问题仅在机器确实需要语义判断处出现。
**绝不做"先填 20 题问卷"**（那会把被服务变成被审问，信任未建立即流失）。

## 5. 责任与合规边界（投资场景必写）

- 系统定位是"把口径与分歧理清楚、按用户口径呈现"，**不构成投资建议**；
- 最终判断权天然在用户——本机制（用户拍板）恰好与之自洽，可在产品文案中
  转危为机（"口径怎么选，永远你说了算"）；
- **"不构成投资建议"必须是交互上的强制，不能只是文档声明**：凡是用户拍过板的
  地方，报告内该处显式标"**这是你的采信，非系统推荐**"（含选择时间与选项），
  由 §2.2 的回显机制承载——回显因此兼做**合规留痕**；系统默认口径的部分则标
  "系统默认口径，可点击改为你的偏好"；
- 若用户维护的口径体系与其历史拍板矛盾，允许一键回退到专家默认并提示差异。

## 7. 里程碑建议（先验"想不想纠"，再验"纠了有没有感"——顺序不能反）

> **评审修正（2026）**：原 M0 把两个独立假设绑在一起测了——
> 假设 A「用户愿不愿意做'纠口径'这个动作」与假设 B「纠完订制感可感知」。
> A 不成立则 B 无从谈起，故拆开、先验 A。另：**机制生效 ≠ 订制感可感知**，
> M0 的核心假设必须可证伪，回显是指标不是锦上添花。

- **M-1 假设 A 纸面验证（先于任何代码）**：用一份真实报告 + 手标分歧点 +
  可点击 mockup，让 2-3 位目标用户**自然浏览**。mockup 必须体现新姿态的两个状态：
  ① **默认并陈**——分歧处的多套说法在首屏就看得见（零操作透明）；② **可选表态**——
  用户想固定口径时才点。**只测两件事：用户读不读得懂并陈？愿不愿意（主动或轻引导
  下）表态一次？** 需不需要解释、会不会觉得烦。观察清单见
  `outputs/paper_test_A/README`（主持人口径：犹豫时长/是否提问/主动探索/情绪）。
  通过线：多数用户无需解释即理解"为什么一个指标有几个数"，且不显排斥；
  表态动作有人愿意做即算 A 通过（允许部分用户只看不表态——那正是"零操作受用"）。
  不通过 → 并陈/表态交互要重设计，M0/M1 全部延后。

  > **进展（2026）**：v1/v2 mockup + 纸面标注版经真实目标用户测试——
  > **假设 A 正式通过**：被测者能注意到多口径、顺利选择偏好口径，
  > 并反馈"定制化很方便"（早期正向信号，指向假设 C）。M0b 进入 B/C 段：
  > 最小点击入口（真人亲手触发纠错 → rep2 变化 → 能否指出、感觉如何）。

- **M0 单用户闭环 demo**：默认专家口径 → 生成一份真实主题报告（复用已验证
  检出+约束+对账）→ 用户真实点一次"纠口径" → 偏好写库 → 二次生成。
  **核心假设（可证伪）：用户能否在第二份报告里一眼指出"哪些地方是因为我的
  选择而变的"。** 验收不是"代码跑通、数字变了"，而是**回显可被用户指认**：
  测试者问"这份和上一份哪里不一样、为什么"，用户须能答出"因为我之前选了 X 口径"。
  答不出 → 订制感为零，机制跑得再顺也没用，回显设计需返工。

  > **结果（2026）**：M0a（机制闭环，5/5 断言）+ M0b（真人假设）均通过——
  > M0b 中真人亲手点选口径后，能感知报告随其选择变化并评价"**体现出个性化**"
  > （= 假设 C"这玩意懂我"而非"哦改个数"）。**产品生死假设（用户愿参与、
  > 订制感可感知有价值）经真人验证成立**。产物：scripts/pref_store.py、
  > m0a_closed_loop.py、m0b_gen_rep2_all.py、m0b_entry.py（flask 可选入口）。

- **M1 提问路由**：分歧清单 → 筛选"需语义判断"项 → 带上下文提问 → 沉淀。
  指标：提问数/报告数收敛曲线、用户完成率。
  **必须在 M0 真实纠错行为之后做**——"问得蠢=流失"需要真实交互来喂，否则是凭空猜。
- **M2 维护面板 + 多领域**：偏好可视化/回退；扩展到 2-3 个领域验证作用域树。
- 引擎侧零改动目标保持：所有新能力收敛在 scripts/产品层。
