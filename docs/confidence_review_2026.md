# 置信度评分工程评审落地（2026）

> 评审来源：产品/工程评审对 `extract_evidence` 确定性置信评分的三条修正 + 一条产品红线。
> 引擎改动范围：**聚合层计分段**（extract_evidence），抽取层 `_sentence_claims` 零改动。

## 一、评审保留的"别改"三条（现状即正确）

1. 叫 **strength/level 不叫 accuracy**——不假装是概率；
2. **单源封顶 low**（0.2+top_cred×0.15）——最可信的源没旁证也不给高，防"一家之言"；
3. **无年份增长率判 low 不互证**——把"假背书"落到规则层。

## 二、修正 ①② 已落地（本提交）

### ① 数量不碾压质量
旧：`≥3 源一致 → 0.5+0.3(n−1)+0.2tc，cap 0.95`——3 个互相独立但都低可信的源
可冲到 0.95/high（tc 权重仅 0.2）。防了"转载假背书"，没防"三个独立骗子"。
新：high 加**质量门槛**——`(n_support≥3 且 tc≥0.6) 或 (n_support==2 且 tc≥0.85)`。

### ② 分档不连续 → 单一连续函数
旧：≥2 源与 ≥3 源两条独立公式，档间倒挂（2 源套 3 源公式会算出 0.95）。
新：多源一致档统一
`score = min(0.95, 0.34 + 0.44×tc + 0.26×(1 − 1/(n_support+1)))`
level 只做显示映射；分歧档分数用主导占比连续式 `0.22+0.30×agree+0.25×tc`，
level 封顶 medium/low（有分歧不配 high，保守设计保留）。

### 验证场景（全部符合预期）

| 场景 | 旧 | 新 |
|---|---|---|
| 3 独立源 cred=0.4 同值 | high 0.95 | **medium 0.71** |
| 3 源 cred=0.9 一致 | high | high 0.93 |
| 2 源 cred=0.9 一致 | high | high 0.91 |
| 2 源 cred=0.7 一致 | high(0.55+0.14…映射 high? 旧若 tc<0.85→medium；评审指的分档断裂) | **medium 0.82** |
| 2 一致 + 1 分歧 | medium | medium 0.65 |
| 单源 0.9 | low | low |
| 同 URL×3 | low | low |

## 三、修正 ③ 拆为独立专项（本提交不实现，原因见下）

评审原话：官方财报/公告这类主张"真源只有一个"，媒体转载不构成独立背书；现公式
把官方单源打 low、把"同数被 3 家媒体转述"冲 high——**方向反了**。

**关键辨析**：问题实质不是"官方源该翻身"，而是**同源传播未折叠**——官方财报被
10 家媒体转载，url 层算 10 个"独立源"→ 假 high。正确解法 = **证据链识别**：

| 信号 | 判定 |
|---|---|
| 句子含"据 X 发布/援引 X/来自 X/X 表示"（X=权威/官方） | 该 claim 的 `chain` 标为 X——转载/引用**不新增证据链** |
| 不同发布者引用同一权威出处 | 同 1 条证据链（n_support 不因转载数上升） |
| 真独立（官方发布 + 审计/第三方各自独立取证） | ≥2 条证据链才可能 high |
| 官方单源 | 1 条证据链 → medium（"官方发布但未独立交叉"），不再因媒体转载虚增 |

实现要点：extract_evidence 层对 claim 增 `chain_id`（来源出处解析，确定性规则，
复用主题词/机构名表）；n_support 改数证据链而非裸 url。**独立 MR + 独立测试，
沿用既有门禁。**（涉及引用识别，改动面与语义风险大于①②，故拆出。）

## 四、产品层红线（已入 product_skeleton §2.2）

**用户决断史只能进"呈现通道"，永远不许进"证据通道"**——否则偏好加权改写机器分
= 回音壁（用户越看越觉得自己选对了，新证据被压暗）。勘误永远压过偏好；偏好只管
"按你的口径展示"。措辞模板："你之前按 X 口径看，新证据显示 Y 更可靠，已帮你
切换，可回退。"详见 `docs/product_skeleton.md` §2.2。
