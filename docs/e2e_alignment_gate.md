# AI 对齐 + 规则归一化闸门：最小验证（2026 · 新能源主题）

> 目的：验证用户拍板的分工边界——**AI 管语义同指（像不像同一话题），
> 规则管结构确定（归一化后是不是同一个键）**——能否让"口径分歧清单"
> 从人工手写变成**规则自动产出**，打通"检出 → 约束 → 报告"闭环。
> 引擎（analyzer/evidence_store）零改动；验证脚本在 scripts/ 层。

## 一、管道设计（AI 管语义、规则管结构）

1. 规则 `_sentence_claims` 抽候选 claim（销量/规模/渗透率/份额/产量/零售类，
   62 句），按句去重；
2. **AI 对齐层**：LLM 对每个数值输出两级判定
   `{topic: 话题规范名, spec: 口径}`——口径（零售/批发/产销）**不许**写进 topic；
3. **规则归一化层**（本次核心）：
   - `_base_topic`：**口径词剥离表**（零售/批发/产销/出口…纯统计环节词）剥 topic
     归同键——"比亚迪零售销量"→"比亚迪销量"；
   - 期间键：优先取 spec 内显式年份，否则规则 claim.year（防跨年排比假簇）；
   - close 去重（700 与 709.8 同表达取一）+ 修饰值过滤（门槛/约/区间词不进清单）；
4. 规则产出分歧清单（同 base topic + 同期 多口径）→ 喂约束式 C 档生成报告。

## 二、迭代与暴露的问题（三版收敛）

| 版 | 做法 | 结果 |
|---|---|---|
| v1 | AI 判单层 entity | 时间未进键→跨年假簇；700/709.8 未去重；1280.9 与 1649 被拆成不同 entity |
| v2 | topic/spec 两层 + year 并入 | 口径词表外仍漏：AI 把"零售/批发"写进 topic 名；门槛词仍进清单 |
| **v3** | **规则剥口径词归键 + spec 内年份作期间键 + 修饰值过滤** | 命中人工 4 陷阱点中的 3 个完整 + 新发现长安福特/自主份额分歧 |

**关键洞察**：AI 不完全服从"口径写进 spec"的指令（"零售销量/批发销量"在中文里
本就是复合指标词）——但规则**不需要 AI 完美**：AI 给自然 topic 名即可，规则用
**确定性词表**剥口径词归同键。语义判断的容错由结构层兜住，这正是分工的意义。

## 三、端到端闭环结果

自动清单（12 行，含少量噪音行如"中国汽车(2025):709.8/75.3单月"）直接喂约束式
C 档 → 报告 **4/4 陷阱点覆盖**：
- T1 新能源销量：1649(中汽协产销)/1531.9(乘联会批发)/1280.9(乘联会零售) 专节列表；
- T2 乘用车总量：3010.3/2955.4/2374.4 三口径分列，并主动解释批发-零售差额=出口 573.9；
- T4 比亚迪：460.2/454.5 分口径小节；T3 出口 709.8/573.9 融入差额解释。
- 噪音行 AI 自行消化（正确理解为"出口总量+单月"），未误导。

## 四、已知边界（如实记录，非本轮修复）

1. **year 桶不一致**：比亚迪 348.5(零售) 落 (2025) 桶、460.2/454.5 落 年? 桶
   （analyzer year 部分缺失）→ 同一实体分两桶各报一次。规则侧年份补全可解；
2. **"出口/国产"词表边界**："新能源汽车出口"被剥"出口"后 base 撞"新能源汽车"，
   261.5(出口) 与总量语义不同却同键——口径词表需按实体类型区分
   （出口是"独立话题"还是"统计环节"取决于主体）；
3. 门槛/预测词靠词表过滤，未见长尾即够用；AI topic 自由命名有轻微漂移
   （'中国汽车'/'中国汽车销量'两写法），剥词表已吸收大部分。

## 五、结论

**分工成立且可闭环**：AI 管语义同指（topic 自然命名即可，允许带口径词），规则管
键归一化（剥口径词/期间键/去重/去噪），自动产出的分歧清单质量足以直接驱动
约束式报告且 4/4 覆盖。**"规则给 AI 的对齐结果设可校验闸门"第一次有了可运行
的原型**。人工清单（上轮）与自动清单（本轮）效果等价——检出环节自动化迈出第一步。
