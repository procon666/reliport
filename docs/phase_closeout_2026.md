## 3. 审计护栏（防口径回潮机制）

1. **test_year_schema_audit.py**：AST 抽取三源（语料/KNOWN/LABELED）全部期望，
   相对值桶 year 非 None 即 FAIL——口径变机器约束，不靠人记忆。首跑即逮到军工
   7.2% 旧口径残留 1 处。
2. **test_label_fixes.py 63 断言**：每个修复成功的缺陷迁出 KNOWN 后固化为正式断言
   （归母 4 / 并列 8 / P3 校准 5 / E1 簇 C 7+ / E2 簇 A 15 / E3 存量同期 7）。
3. **KNOWN REVISIT 机制**：KNOWN 条目意外通过 → exit 1 报警，防清单腐化；判定用
   `strict_num_eq`（数值精确相等，KNOWN 期望逐字摘录不需 close 容忍——close 会让
   同句相近值误判已修好，军工 7%/7.2% 教训）。
4. **分布 diff 纪律**：每次引擎改动须做固定清单（140 句 242 claims）subject/year
   分布前后对比，只允许预期变更（E1 的 27 处全为相对值→None、E2 的 27 处全可解释、
   E3 的 6 处全为预期），非预期漂移即失败。

## 6. 风险提醒（封板必读）

1. **KNOWN 22 条是已知业务边界**：下游使用方须知情——遇到 S1-S4 触发句式会产出
   不理想主体，**不要当 bug 提**；仅当真实业务大规模复现形成新簇，才重新评估引擎
   改动（回 §9 流程）。
2. **固定 label 集 86.9% ≠ 线上业务准确率**：历史测试集分数不能外推线上；线上效果
   以**端到端真实文档跑分**（召回/冲突/一致性）为主指标。
3. **后续改解析逻辑沿用老框架**：真实语料归集 → 统计成簇 → 达触发阈值（×3-4）才
   开专项 → 严格门禁 + 分布 diff → 迁出 KNOWN 升级断言。**拒绝单点打补丁**。
4. **口径漂移是最大隐性风险**：E1 曾发现语料 8 处旧口径残留、P3 复核漏网 12亿/
   1.7万 等。任何新标注/新归集必须过 `test_year_schema_audit.py`，禁止按旧直觉写
   "增长率挂报告年"。
5. **引擎确定性红线**：本项目**不使用 LLM**。所有解析为规则/正则，可解释、可测试、
   可离线——此约束是整套治理方法论的前提，引入黑盒会破坏 KNOWN/审计/断言体系。

### A.2 extract_evidence 输出字段全景（schema v2 后）

证据项 dict：`subject`(归一) / `subject_raw`(原文,claim 级) / `indicator` / `year` /
`label` / `n_sources` / `claims`(含 anchor/revision/sentence) / `clusters`(四门归簇:
值 close+量纲+锚一致+None 锚不抬) / `adopted`(含修正优先) / `level` / `score` /
`reason`(字符串,向后兼容) / **`verdict`**=`{kind, detail}`。

`verdict.kind` 枚举：`一致` / `单源` / `修正` / `键失真`（同桶多量纲=异物同桶残留）/
`分歧-真冲突` / `分歧-无主导` / `分开呈现`（None 锚相对值）。

  同桶 2 源但 adopted 单源 → low（比较期未知不互证，防假冲突）。`test_near_synonyms`
  断言已同步更新并注释原因。
