# 可信订制报告引擎

> **敢说哪里不确定的报告，才是可信的报告。**

一个面向中文数据主题的**可信研究助手**：规则化抽取数值声明 → 跨来源交叉验证 → 按你自己的口径产出带**证据链下钻**的行业报告。

**核心承诺**：大模型不编数 · 每个数可溯源 · 口径冲突看得见 · 沉淀用户口径选择。

**在线演示（裸 LLM 对照实验）**：https://a424650792e3ee278.app.workbuddy.host

---

## 一、为什么做这个（设计初衷）

做行业研究/行情观察类内容时，反复撞到四个真实痛点，它们分别对应系统的一条核心承诺：

| 痛点 | 系统承诺 | 落到哪个机制 |
|---|---|---|
| AI 写稿**编数字**，或把"大概 700 万"悄悄写成精确数，读者无法分辨 | **素材外数字 = 0**，对不上素材原词的数字宁缺毋滥 | 出厂对账闸门（OK/概算/疑不符/无出处）+ 写作纪律（无出处 > 4 触发重写） |
| 同指标多家机构报不同数（IDC 21.2% vs Counterpoint 20%），常见做法是**取平均或挑个好看的**，把冲突藏掉 | **冲突不遮掩**，多口径并陈，把"按谁看"的决定权交给读者 | 拍板点检出（decisions.json）+ 口径差异说明节 + 定制工作台 |
| 强证据和弱证据混在一起写，读起来都像"事实" | **强弱分得开**，置信度不是盖章，而是让强证据敢断言、弱证据敢示弱 | 强度措辞规范 + 示弱核查闸门 + 浮层置信分级 |
| 换个角度就换一套结论（按出货量 vs 按零售额），报告却只有一种叙事 | **报告会记住你的口径**，同一领域后续报告自动按你的选择组织叙事 | 偏好库（pref.json）+ 口径偏好强约束注入 |

一句话概括设计取舍：**不信任"一次生成"，用规则闸门把 LLM 锁在"语义对齐 + 写作"的笼子里**——LLM 负责懂人话，规则负责讲证据。

## 二、三条设计铁律

1. **抽取引擎封板**：`research_agent/analyzer.py` 是所有可信度的地基（谁从句子抽数字、怎么把多来源归成一个证据、怎么给裁决）。它被语料回归 + 30 项 CI 锁死；后续优化**不许改引擎**，只能在上层打补丁——这让系统可回归、可解释。
2. **LLM 只做"语义"与"写作"，一切"判定"用规则**：LLM 管"这句话里的 3.3% 属于哪个话题、什么统计口径、该行业有哪些权威机构"；规则管"同一实体不同数字是否构成分歧、给什么置信等级"。**判定可复现、可测试、可审计，而这三样正是概率模型给不了的。**
3. **每一层都要"可下钻到证据"**：报告里任何一个数字，向上能追溯到素材原句、原报道标题、原文链接；对不上原文的数字在生成时就会被出厂对账闸门拦住。

## 三、架构分层

```
┌─────────────────────────────────────────────────────────┐
│  ④ 产品层  app.py · pref_store · theme_run · selfcheck    │  界面 / 偏好 / 编排 / 自检
├─────────────────────────────────────────────────────────┤
│  ③ 呈现层  render_report.py · strength_layer.py           │  置信度可视化 · 证据链 · 阅读地图
├─────────────────────────────────────────────────────────┤
│  ② 裁决层  decision_layer.py · ai_alignment_demo.py       │  语义对齐 · 归簇 · 拍板点判定
│            e2e_audit_demo.py                              │  出厂对账（数字可溯源闸门）
├─────────────────────────────────────────────────────────┤
│  ① 抽取引擎 research_agent/analyzer.py（已封板）            │  数值 claim 抽取 · 跨源证据聚合
└─────────────────────────────────────────────────────────┘
```

**一次完整运行**：

```
主题 + 关注点 + 标识
  → 多轮对撞导向抓取（泛抓 → 机构识别 → 定向补抓 → 质量闸门 → 对撞体检，不达标触发补抓）并通过LLM对权威机构的官网信息进行一手资料获取以保底。
  → 分歧检出（规则抽句 → LLM 语义对齐 topic/spec → 规则归簇）
  → 强度账（每个关键数标注 多源一致/中等/单一来源/需并陈）
  → 约束式写作（LLM 照分歧清单逐条交代，注入用户口径偏好）
  → 双重闸门（出厂对账 + 示弱核查，超标附反馈重生成一次）
  → 拍板点检出（同话题多机构不同数 → 定制工作台）
  → 增强渲染（阅读地图 + 正文 ⓘ 锚点 + 浮层证据链）
```

## 四、关注点

- **多轮对撞导向抓取**：单轮泛抓常只命中一家机构（如 IDC），对立的 Canalys/Counterpoint 明明存在却进不来。现在由 **LLM 按主题动态发现行业权威机构**（换光伏、白酒等行业不会因固定名单不对口而失手），规则在稿内**识别**机构，再用**对撞体检**判断"抓到多家机构名 ≠ 抓到多口径对撞"，不达标触发第三轮定向补抓。
- **伪多源甄别**：`_assign_origins` 用**内容指纹索引 + 并查集**做逐字转载/镜像的可传递折叠（A≡B、B≡C ⇒ 同源），并选代表文档防止低可信镜像虚增来源数；浮层对"同源多页传播"给出黄字提示（属转载扩散，不构成独立复测），**把"独立验证"与"传播采纳"两个置信含义分开**。
- **置信度是证据强度，不是真值概率**：多源独立来源数、来源可信度、是否存在分歧簇、年份锚定共同决定档位；单源封顶低置信，无年份的相对值不互证——**防的是"假背书"与"假冲突"**。
- **双通道红线（防回音壁）**：用户决断史只进**呈现通道**，永不进**证据通道**；偏好只决定"按你的口径展示、措辞、高亮谁"，**新证据与既有采信冲突时，勘误压过偏好**。
- **约束式写作**：规则出题、AI 答题——分歧清单、强度措辞规范、用户口径偏好共同约束生成，写作纪律用系统提示词固定。

## 五、实测成绩

| 项 | 结果 |
|---|---|
| 语料回归 | **79/79** 句级全对（P0 起保持） |
| 真实素材盲测（四靶场） | 数值召回 **61/61、27/27、30/30、34/34（152/152，100%）** |
| CI 门禁 | **30 项全绿**（语料 + KNOWN 边界 22 条 + 修复固化断言 63 条 + 专项测试 + 四靶场） |
| 出厂对账 | 无出处数字 **0**、无依据强断言 **0**（多主题复测；NBA 主题一轮 17 → 1） |
| 口径分歧检出 | 手机主题 **0 → 15** 个真实跨机构对撞点（三层归因修复后） |
| 抽取引擎 | ~2700 行，封板版本，多领域实测 |

**三组对照实验**（`scripts/compare_baseline.py`）：裸 LLM + 素材 / 裸 LLM 纯记忆 / 本系统，同一素材、同一对账器下对比——证明"编造数字 0、口径冲突全部显式并陈"不是自评。

## 七、已知边界（主动交代）

1. **拍板点数量取决于素材生态**，不由代码决定：多机构对同一指标给数的主题（汽车 / 手机 / 新能源 / 俄乌）拍板最有用；单源综述型主题（部分行业盘点、宏大历史题材）拍板点少或为 0，价值退化为"看证据链 + 标记我信的来源"。
2. **同源洗稿级改写未做链级归并**：逐字转载/镜像已折叠，轻度改写与"按源头机构归并"尚未实现（浮层目前以黄字提示，等级未改）。
3. **时效为软性降权，无过期硬门限**：旧素材不会被自动剔除，只靠检索时点 + 裁决排序 + 年份标注降权。
4. 单机本地工具：无鉴权、无流式进度；报告目前仅中文生成（英文素材已支持阅读）。
5. **真人实测样本量小**：机制层断言已闭环，但真人验证目前只有少数被试（N=1），"用户是否愿意纠口径、能否感知报告变化"尚无统计意义上的结论，真实应用场景有待更大样本验证。

## 八、技术栈

- **语言/框架**：Python 3 · Flask（本地 Web）· PyQt5（桌面版）· reportlab（PDF 导出）
- **LLM / 检索**：OpenAI SDK 接 DeepSeek（语义对齐、写作）· Tavily（联网检索）
- **抓取/解析**：requests · trafilatura · BeautifulSoup4
- **工程**：分层架构 · 环境变量集中配置 · 素材指纹缓存 · 回归测试 + CI 门禁 · 结构化文档沉淀

## 九、说明

本项目为个人研究工具，报告内容由 LLM 依据检索素材生成并经规则闸门校验，**不构成任何投资建议**；口径怎么选由使用者决定。
